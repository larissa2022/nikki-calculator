# 数据库环境信息

## 0. 用途

本文档记录 Supabase 项目的环境划分，只保存非敏感信息。

不要在本文档中记录：

- 数据库密码
- service role key
- access token
- refresh token
- 真实用户隐私数据

## 2. 当前策略

- Git 分支与环境对应关系以 [`../governance/BRANCH_ENVIRONMENT_POLICY.md`](../governance/BRANCH_ENVIRONMENT_POLICY.md) 为准。
- `main` 只对应 production。
- `develop` 只对应 development / preview。
- 本地开发应优先连接 development。
- 当前本地 Supabase link 已切换到 development：`tfwejruvdahonacyldrg`。
- 数据库 migration 必须先在 development 验证。
- production 只执行已验证、已备份、已记录的变更。
- 切换 Supabase link 前，必须确认当前目标环境。
- 不运行数据库命令前，先确认 Supabase project ref；production ref 只能用于明确批准的生产操作。

## 3. 本地连接建议

连接 development：

```powershell
supabase link --project-ref tfwejruvdahonacyldrg
```

连接 production 前必须先确认：

```powershell
supabase link --project-ref fopyjewbsvusftpqbtml
```

确认当前链接：

```powershell
supabase status
```

说明：`supabase status` 会检查本地 Docker Supabase 容器。如果本地容器未启动，可能出现 `No such container: supabase_db_...`。这不代表远程 project ref 切换失败。可通过 `supabase/.temp/project-ref` 确认当前 linked project。

## 4. 环境变量

本地开发 `.env.local` 应使用 development：

```text
VITE_SUPABASE_URL=https://tfwejruvdahonacyldrg.supabase.co
VITE_SUPABASE_ANON_KEY=<从 Supabase Dashboard 复制 anon public key>
```

注意：

- 可以使用 anon public key。
- 不要把 service role key 写入前端环境变量。
- 不要提交 `.env.local`。
