# 数据库变更记录

## 0. 使用说明

本文档用于记录 Supabase 数据库的每一次结构变更、RPC 变更、RLS 变更和批量数据变更。

记录原则：

1. 每个 migration 或线上 SQL 操作都必须有记录。
2. 生产执行前先填写“变更计划”。
3. 生产执行后补充“执行结果”。
4. 批量数据更新必须记录预检 SQL、影响行数和复查结果。
5. RPC 替换必须记录旧函数备份方式和回滚方案。

## 2026-06-27 17:20 - update_profile_username_rpc

### 基本信息

| 项目 | 内容 |
| --- | --- |
| 变更类型 | RPC |
| 目标环境 | development，生产待确认 |
| migration 文件 | `supabase/migrations/20260627172000_update_profile_username_rpc.sql` |
| 关联缺陷 | `BUG-20260627-013` |
| 执行人 | Codex |
| 确认人 | 待验证 |

### 变更目的

- 允许普通登录用户修改自己的专属代号 `profiles.username`。
- 避免开放 `profiles` 整行 update 权限，防止用户绕过前端修改 `role_level`、积分、额度等敏感字段。
- 修复昵称保存后页面仍显示匿名代号或邮箱的问题。

### 影响范围

| 对象 | 影响 |
| --- | --- |
| 表 | `profiles` |
| 字段 | 仅通过 RPC 更新当前用户自己的 `username` 和 `updated_at` |
| RPC | 新增 / 替换 `update_profile_username(p_username text)` |
| RLS / Policy | 不新增普通用户整行 update policy |
| 前端模块 | `UserProfile.vue`、`MainView.vue`、`App.vue`、`AuthBar.vue` |
| 线上用户影响 | 未推生产前无影响；推生产后用户可设置并立即看到专属代号 |

### 变更内容

- RPC 校验用户必须已登录。
- RPC 校验用户名非空、长度不超过 24 个字符，且不能使用 `匿名搭配师_` 保留前缀。
- RPC 使用 `security definer` 只更新 `auth.uid()` 对应 profile。
- 前端保存昵称后立即使用 RPC 返回的 profile 做本地展示更新。
- 顶部用户展示优先显示 `profile.username`，未设置时继续显示邮箱。

| --- | --- |

| 类型生成 | 待 dev migration 应用后执行 `npm.cmd run db:types` |
| 本地构建 | `npm.cmd run build` 成功 |
| production | 未执行 |
