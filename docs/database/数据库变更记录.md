# 数据库变更记录

## 0. 使用说明

本文档用于记录 Supabase 数据库的每一次结构变更、RPC 变更、RLS 变更和批量数据变更。

记录原则：

1. 每个 migration 或线上 SQL 操作都必须有记录。
2. 生产执行前先填写“变更计划”。
3. 生产执行后补充“执行结果”。
4. 批量数据更新必须记录预检 SQL、影响行数和复查结果。
5. RPC 替换必须记录旧函数备份方式和回滚方案。

## 2026-06-27 09:30 - require_numeric_game_id

### 基本信息

| 项目 | 内容 |
| --- | --- |
| 变更类型 | RPC |
| 目标环境 | development，生产待确认 |
| migration 文件 | `supabase/migrations/20260627093000_require_numeric_game_id.sql` |
| 关联缺陷 | `BUG-20260625-003` |
| 执行人 | Codex |
| 确认人 | 待确认 |

### 变更目的

- 缺失图鉴提交时，短编号必须填写。
- 短编号只允许数字。
- 防止用户绕过前端直接调用 RPC 写入空值、`N` 或非数字短编号。

### 影响范围

| 对象 | 影响 |
| --- | --- |
| 表 | 无结构变更 |
| 字段 | `pending_clothes.game_id`、`clothes.game_id` 写入值收紧为数字字符串 |
| RPC | 替换 `submit_clothing_contribution(...)` |
| RLS / Policy | 无 |
| 前端模块 | `MissingItemsQueue.vue`、`ClothesEntryForm.vue` |
| 线上用户影响 | 未推生产前无影响；推生产后非数字短编号提交会被拒绝 |

### 变更内容

- RPC 内 trim `p_game_id` 为 `v_game_id`。
- `v_game_id` 为空时抛出“短编号不能为空”。
- `v_game_id` 非数字时抛出“短编号只允许填写数字”。
- 自动入库与待审核写入统一使用 `v_game_id`。

### 执行结果

| 环境 | 结果 |
| --- | --- |
| 本地构建 | `npm.cmd run build` 成功 |
| development | 待执行 `supabase db push` |
| production | 未执行 |

### 回滚方案

- 新建 migration，恢复上一版 `submit_clothing_contribution(...)` 函数定义。
- 前端可回滚 `MissingItemsQueue.vue` 和 `ClothesEntryForm.vue` 的短编号校验逻辑。

## 7. RPC 变更记录要求

如果变更 RPC，必须记录：

- RPC 名称。
- 旧函数定义备份位置。
- 新函数参数。
- 新函数返回值。
- 权限 grant / revoke。
- 是否 `security definer`。
- 是否校验当前用户。
- 是否校验角色。
- 是否校验自审。
- 回滚 SQL。

## 8. RLS 变更记录要求

如果变更 RLS，必须记录：

- 表名。
- 是否启用 RLS。
- 新增 / 修改 / 删除的 policy。
- anon 用户结果。
- authenticated 普通用户结果。
- admin 用户结果。
- super_admin 用户结果。
- 是否存在越权读取风险。
- 是否存在误封正常功能风险。
