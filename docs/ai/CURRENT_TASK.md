# 当前任务看板

> 最后更新：2026-07-26 10:02（北京时间）

## 当前任务

- 建立可由社区参与、又能阻止自审的重审池基础，让争议资料不会只能等待管理员处理。

## 为什么做

- 待补套装、字段冲突、字段缺失和报错转重审需要统一追踪；如果只交给管理员处理，管理员不在线时会长期积压。

## 已经完成

- development 已建立重审项、来源审计和社区候选修正版三张基础表，保留后续自动处理和管理员兜底空间。
- 已验证社区读取与候选提交；原提交者和来源参与者不能自审，匿名访问被拒绝，测试事务回滚后没有残留数据。

## 当前进度

- 完成阶段：DB-6 已在 development 生效并通过业务、权限、本地全量重放、类型和 schema 快照验证；当前尚未接入自动建项、自动关闭、投票或正式库修改。

## 下一步

- 接入缺套装入库自动创建重审项，并在绑定正式套装后自动关闭待补状态。

## 需要负责人决定

- 启动下一项接入任务时，需要单独授权对应 development migration；production、`main` 和 merge 继续不在范围内。

## 通用边界

- `main`、production、database / Supabase / Vercel 写入、migration、env、PR merge、历史改写、分支删除和 `RULES.md` 修改仍需分别明确确认。

## Rollback

- 如需停用 DB-6，新增 patch migration 先撤销社区入口并保留三张表；确认无数据和下游依赖前不删表、不改写 migration history。
