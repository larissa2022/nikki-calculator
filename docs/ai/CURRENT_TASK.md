# 当前任务看板

> 最后更新：2026-07-26 12:47（北京时间）

## 当前任务

- 让用户可以明确选择“所属套装待确认”，服装正常入库后自动进入社区重审池，并在绑定正式套装后自动关闭待补状态。

## 为什么做

- “纯散件”和“暂时不知道所属套装”此前都保存为空套装，数据库无法安全区分；必须增加明确状态，避免纯散件被错误送入重审池。

## 已经完成

- development 已建立重审项、来源审计和社区候选修正版三张基础表，保留后续自动处理和管理员兜底空间。
- 已验证社区读取与候选提交；原提交者和来源参与者不能自审，匿名访问被拒绝，候选 ID 和提交时间只能由数据库生成，测试事务回滚后没有残留数据。
- development 已完成“所属套装待确认”的用户、管理员新建与正式库已有补全入口，以及自动建项、来源保留、绑定正式套装自动关闭和事务回滚验证；历史纯散件保持原语义，测试事务没有持久残留。

## 当前进度

- 待发布阶段：接入 migration 已在 development 应用并通过结构、权限、事务、Advisor、类型、测试和构建验证；投票、最终处理和报错入口继续不在本次范围。

## 下一步

- 对当前数据库主 PR 做合并前只读审计，确认范围、验证证据和 rollback 完整。

## 需要负责人决定

- 当前无需新增产品决定；PR merge、production 和 `main` 仍需分别明确授权。

## 通用边界

- `main`、production、database / Supabase / Vercel 写入、migration、env、PR merge、历史改写、分支删除和 `RULES.md` 修改仍需分别明确确认。

## Rollback

- 如需停用本次接入，新增 patch migration 让“所属套装待确认”重新只停留在 pending、停用自动关闭触发器；保留既有重审项、来源和审计事实，不改写 migration history。
