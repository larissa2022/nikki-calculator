# 测试清单

用途：记录需要人工或自动验证的测试项，帮助确认改动是否满足预期且未引入回归。

## Preview / Production 人工回归测试清单

### 1. 衣柜保存与刷新后数量稳定

- 测试目标：确认用户录入大量衣服后，刷新页面不会从几千件异常缩水到一百多件。
- 操作步骤：
  1. 使用已登录账号进入“我的衣柜”。
  2. 记录当前总收集数量。
  3. 连续新增或取消若干衣服，触发云端同步。
  4. 等待同步完成提示消失。
  5. 刷新页面并重新进入“我的衣柜”。
  6. 对比刷新前后的总收集数量和最近操作的衣服状态。
- 预期结果：
  - 刷新后总收集数量稳定。
  - 最近新增或取消的衣服状态正确保留。
  - 页面不长时间卡在“正在同步到云端”。
- 是否通过：通过

### 2. 按分类 + 短编号录入衣柜

- 测试目标：确认用户可通过选择分类并输入短编号批量录入已有图鉴衣服。
- 操作步骤：
  1. 进入“录入衣柜”。
  2. 选择一个分类，例如“发型”或“连衣裙”。
  3. 输入多个短编号，例如 `0001, 0002, 0003`。
  4. 提交录入。
  5. 查看录入结果报告。
  6. 返回“我的衣柜”确认对应衣服已加入。
- 预期结果：
  - 正式库存在的编号进入“本次成功录入”。
  - 未匹配到图鉴编号的项目进入缺失提示。
  - 成功录入的衣服刷新后仍保留在衣柜中。
- 是否通过：通过

### 3. 管理员审核卡片文案

- 测试目标：确认管理员审核卡片不再出现技术感文案，并按确认口径展示状态。
- 操作步骤：
  1. 使用管理员账号进入“图鉴管理”。
  2. 查看“自动入库候选”中的不同卡片。
  3. 分别检查全部一致、多数一致但有不同意见、未达 5 人、人数不足的展示。
  4. 打开卡片详情或入库表单，查看提示文案。
- 预期结果：
  - 页面不出现“版本 / 变体 / 字段组合 / 冲突版本 / 一致提交”。
  - 使用“资料一致情况 / 最多人认可 / 不同意见 / 可按多数入库 / 需要继续收集”等文案。
  - 全部一致显示“可入库”。
  - 多数一致但有不同意见显示“可按多数入库”。
  - 有不同意见但未达 5 人显示“需要继续收集”。
  - 人数不足显示“人数不足”。
- 是否通过：通过

### 4. 正式库已有但资料不全的补全路径

- 测试目标：确认正式库已有同名同分类衣服但资料不全时，管理员可从 pending 补全缺失资料。
- 操作步骤：
  1. 在管理员审核页面找到“正式库已有但资料不全”的待处理项。
  2. 打开补全表单。
  3. 检查名称、分类、短编号、星级、五组属性、套装状态、特殊标签等字段。
  4. 补齐缺失字段并提交。
  5. 返回正式库或前台图鉴页面检查该衣服资料。
- 预期结果：
  - 提交不因唯一约束重复而失败。
  - 正式库已有记录被补齐缺失资料。
  - 已有的非空资料不被意外覆盖。
  - 页面给出清晰的成功或失败提示。
- 是否通过：通过

### 5. Pending 状态变化

- 测试目标：确认审核或补全后，相关 pending 记录状态按预期变化。
- 操作步骤：
  1. 在管理员页面记录待处理项数量。
  2. 对一个可入库或可补全的项目执行处理。
  3. 处理完成后刷新管理员页面。
  4. 查看该项目是否仍出现在原待处理列表。
  5. 如页面提供状态信息，检查状态是否从 pending 变为 approved、re_review 或其他预期状态。
- 预期结果：
  - 已处理项目不再重复出现在原待处理列表。
  - 未入库的不同意见提交不会被误标为已入库。
  - 状态变化和页面展示一致。
- 是否通过：通过

### 6. 提交者衣柜写回

- 测试目标：确认用户提交的缺失衣服入库或补全后，会自动进入提交者衣柜。
- 操作步骤：
  1. 使用普通用户提交一个缺失图鉴项。
  2. 使用管理员账号审核通过或补全该项目。
  3. 回到普通用户账号。
  4. 进入“我的衣柜”搜索该衣服。
  5. 刷新页面后再次检查。
- 预期结果：
  - 审核通过或补全后，该衣服出现在提交者衣柜中。
  - 刷新后仍保留。
  - 不会误加入未参与提交的用户衣柜。
- 是否通过：通过

### 7. 套装选择与刷新

- 测试目标：确认所属套装加载稳定，选择套装或无关联套装后不会卡死，刷新后展示一致。
- 操作步骤：
  1. 进入缺失图鉴补录或管理员补全表单。
  2. 点击“所属套装”输入框。
  3. 搜索已有套装并选择。
  4. 再测试选择“无关联套装（纯散件）”。
  5. 提交或关闭后刷新页面。
  6. 重新打开同一表单或相关列表检查展示。
- 预期结果：
  - 套装列表可以正常出现。
  - 选择已有套装后展示套装名称。
  - 选择无关联套装时在输入框内清晰展示，不出现框外重复提示。
  - 页面不假死、不长时间空白。
- 是否通过：通过

### 8. 生产环境不显示 Vue DevTools

- 测试目标：确认 production 构建不会加载 Vue DevTools。
- 操作步骤：
  1. 打开 production 站点。
  2. 打开浏览器开发者工具。
  3. 查看控制台和扩展面板。
  4. 刷新页面后再次确认。
- 预期结果：
  - 生产环境不出现 Vue DevTools 注入提示。
  - 不加载开发环境专用调试工具。
  - 页面正常渲染，无构建相关报错。
- 是否通过：通过
